# 🏛️ NagarSetu (नगर सेतु)
### Operator-Facing AI Civic Complaint Triage and Accountability Engine

> **NagarSetu** is an intelligent decision-support workbench built for municipal zone office operators. It transforms unstructured, multi-channel complaint exports (state helplines, municipal apps, WhatsApp/citizen messages, social media, walk-in petitions) into structured, prioritized, and explainably-routed civic tickets while maintaining absolute immutability of raw municipal records.

---

## 📌 Project Overview & Core Purpose

In municipal administration, zone complaint desks receive thousands of heterogeneous complaints across state grievance portals, WhatsApp helplines, social media mentions, and physical petitions. These records suffer from:
- Inconsistent language and colloquial phrasing (Hindi, Devanagari, English, and Hinglish)
- Misrouted departmental assignments causing administrative latency
- Overlooked life-safety hazards buried under mundane complaints
- Repeated citizen reports for the same incident treated as separate issues, inflating backlog metrics
- Lack of explainable accountability or weekly digest metrics

**NagarSetu** bridges this gap. It acts as an **operator-facing, read-only AI triage engine** that assists human desk operators by recommending department routing with verifiable evidence, detecting geographic clusters, applying deterministic urgency rules, drafting citizen acknowledgements, and generating executive weekly accountability digests.

## 🚫 Hard Architectural Constraints & Operating Boundaries

Strictly governed by [AGENTS.md](file:///c:/Users/Harshit%20panwar/Desktop/PROGRAMMING/NagarSetu/AGENTS.md):

1. **Internal Operator Persona**: NagarSetu is **NOT** a citizen-facing mobile app or public complaint submission portal. It is an administrative decision-support workbench for zone office complaint desk operators.
2. **Read-Only & Immutability of Source Data**: All operations over the raw imported dataset (`data/raw/`) are strictly read-only. Scripts, workers, or transformations never modify, overwrite, or delete raw input files. All processed data resides in `data/processed/` or application tables.
3. **Zero Live Connectors**: Zero network connections to government helplines, CM/State helpline endpoints, municipal ERPs (e.g. e-Nagarpalika), or live social media APIs.
4. **No Reverse Sync**: Never write, push, or sync data back to original source systems. All triage actions are self-contained within NagarSetu.
5. **Human-in-the-Loop Acknowledgement Dispatch**: Acknowledgements generated by AI are *drafts only*. No autonomous dispatch. Messages are only marked approved after explicit human operator confirmation and remain strictly within internal storage (no live SMS/email transmission).
6. **Deterministic Validation Governs AI Recommendations**: AI models propose department, category, and urgency. Deterministic business logic validates outputs against official configuration files (`config/departments.json`, `config/urgency_rules.json`, `config/routing_rules.json`, `data/gazetteer/`). Public safety hazards (live electrical wires, open manholes) unconditionally override AI proposals to `CRITICAL`.
7. **Explainability at Individual Ticket Level**: Every routing recommendation must supply inspectable evidence: matched keywords, department charter clauses, rule IDs, and confidence scores. Black-box decisions are strictly disallowed.
8. **Anti-Hallucination & Truthfulness Directive**: Missing fields are marked `UNKNOWN` or `UNSPECIFIED` (never invented). Median resolution times are computed strictly from verified database records with both `created_at` and `resolved_at` (never fabricating SLAs). Benchmark metrics are computed strictly against ground-truth held-out data (`data/test/benchmark_held_out_30.csv`).
9. **Prototype Disclaimer**: All synthetic demo records, prototype gazetteer boundaries, and early-warning heuristics are explicitly tagged with `[PROTOTYPE_ASSUMPTION]` and `DEMO / SYNTHETIC BENCHMARK`.

## 🔄 End-to-End User Story Flow

The system processes complaints through 14 distinct stages:

```
[1. Exported CSV Batch] ──► [2. Multimodal Preprocessing (Text / WAV Audio / JPG Photo)]
                                    │
[3. Indic Language Normalization] ◄─┘
         │
         ▼
[4. AI Classification (Dept, Category, Subcategory)]
         │
         ▼
[5. Deterministic Urgency & Safety Overrides (URG_RULE_001 Live Wire Hazard)]
         │
         ▼
[6. Locality Normalization (Gazetteer Ward/Zone Resolution)]
         │
         ▼
[7. Explainable Routing Recommendation (Keywords, Charter Clauses, Rule IDs)]
         │
         ▼
[8. Incident Clustering & Duplicate Detection (DSU Connected Components)]
         │
         ▼
[9. Operator Decision Desk (Confidence Tiers, Granular Field Overrides with Rationale)]
         │
         ▼
[10. Citizen Draft Acknowledgement Sign-off (Internal Approval Boundary)]
         │
         ▼
[11. Chronological Audit Trail (Operator ID, Timestamp, Diff Log)]
         │
         ▼
[12. Weekly Departmental Accountability Digest (Truthful Resolution Times, Zero Fake SLAs)]
         │
         ▼
[13. Emerging Issue Volume Surge Alerts (Heuristic Baseline Comparison)]
         │
         ▼
[14. Held-Out Benchmark Evaluation (30 Ground-Truth Cases, Confusion Matrix, Error Inspector)]
```

## 🛠️ Technology Stack

| Layer | Technology | Purpose & Rationale |
| :--- | :--- | :--- |
| **Frontend** | React 18 + TypeScript + Vite | Reactive, type-safe operator workbench with sub-second responsiveness |
| **Styling** | Tailwind CSS + Lucide React | High-contrast, clean administrative UI optimized for zone office desk operators |
| **Backend** | FastAPI + Python 3.10+ | Asynchronous ASGI engine with Pydantic v2 schema enforcement and auto OpenAPI docs |
| **Data Models** | SQLAlchemy 2.0 (PostgreSQL / SQLite) | Relational persistence with immutability guarantees (`ImmutableDataError`) |
| **AI / LLM** | Google Gemini API (`gemini-2.5-flash`) | Fast multimodal comprehension, Devanagari/Hinglish understanding, structured JSON |
| **AI Fallback** | Deterministic Keyword Engine | Seamless zero-downtime offline fallback if Gemini API key is missing or quota is exhausted |
| **Analytics** | Recharts | Departmental workload distributions, cluster reductions, and confusion matrices |

## 💻 Local Setup & Running Instructions

### Prerequisites
- **Python**: 3.10, 3.11, or 3.12
- **Node.js**: 18.x or 20.x with `npm`
- **Git**

### 1. Clone & Environment Setup
```bash
git clone https://github.com/your-org/NagarSetu.git
cd NagarSetu
```

Copy the example environment configuration:
```bash
cp .env.example .env
```

Configure your `.env` variables as needed:
```ini
# Environment Mode
ENVIRONMENT=development
PROJECT_NAME="NagarSetu"

# Database Configuration (SQLite default for zero-friction local dev; PostgreSQL supported)
DATABASE_URL=sqlite:///data/nagarsetu_dev.db

# Google Gemini API Key (Optional: system runs in Graceful Deterministic Fallback mode if unset)
GEMINI_API_KEY=your_gemini_api_key_here
MODEL_VERSION=gemini-2.5-flash
PROMPT_VERSION=classification_v1.0

# Server & CORS
ALLOWED_ORIGINS=["http://localhost:5173", "http://127.0.0.1:5173"]
API_V1_PREFIX=/api/v1
```

> **Note on AI Fallback**: If `GEMINI_API_KEY` is not provided, NagarSetu automatically switches to its built-in **Deterministic Keyword Fallback Engine**. All classification, urgency scoring, routing, clustering, and UI capabilities remain 100% functional.

---

### 2. Backend Setup & Run
```bash
# Navigate to backend directory
cd backend

# Create and activate virtual environment
python -m venv venv
# On Windows PowerShell:
.\venv\Scripts\Activate.ps1
# On Linux/macOS:
source venv/bin/activate

# Install backend dependencies
pip install -r requirements.txt

# Seed taxonomy, gazetteer, and sample data
python scripts/seed_data.py

# Start the FastAPI ASGI server
uvicorn app.main:app --reload --port 8000
```
- **Backend API**: `http://localhost:8000`
- **Interactive Swagger Docs**: `http://localhost:8000/docs`
- **System Health Check**: `http://localhost:8000/health`

---

### 3. Frontend Setup & Run
Open a separate terminal window:
```bash
# Navigate to frontend directory
cd frontend

# Install Node.js dependencies
npm install

# Start Vite development server
npm run dev
```
- **Operator Workbench UI**: `http://localhost:5173`
