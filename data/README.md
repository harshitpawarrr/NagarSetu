# Data Storage Architecture & Policy

This directory houses the datasets utilized by the **NagarSetu** triage engine.

## Directory Structure

- `raw/`: **Strictly Immutable**. Exported batches from municipal helplines, state portals, and social media channels.
  - `raw/demo/synthetic_complaints_40.csv`: Realistic 45-row synthetic dataset designed for ingestion and pipeline validation.
    * 42 valid multilingual complaints across English, Hindi (Devanagari), and Hinglish covering 5 civic channels (`state_helpline`, `municipal_app`, `elected_rep_message`, `social_media`, `walk_in_petition`).
    * Varied column headers (`ticket_id`, `created_at`, `complaint_text`, `address`, `voice_note_path`, `photo_url`, `photo_caption`, `complainant_phone`, `citizen_ward_claimed`).
    * Multimodal records: Text-only, Voice note + metadata (`voice_note_path`), and Photo + caption (`photo_url` + `photo_caption`).
    * Includes 3 intentional edge-case validation rows:
      - Row 43: Missing complaint ID (rejected by validator).
      - Row 44: Intra-batch duplicate ID `CMP-DEMO-001` (skipped/flagged as duplicate).
      - Row 45: Missing all modalities (text, audio, image all empty; rejected without hallucination).
- `processed/`: Structured, standardized, and enriched complaint records generated by the ingestion and triage pipeline.
- `test/`: Held-out labelled test dataset reserved exclusively for evaluating classification, routing, and urgency accuracy.
- `gazetteer/`: Reference tables containing Zone, Ward, Locality, and Landmark mappings for deterministic address normalization.

## Data Governance Rules
1. Never modify or delete any file placed inside `raw/`.
2. Do not commit sensitive citizen PII (personal identification numbers, raw phone numbers) to version control.
3. Test sets in `test/` must not be used for model prompt few-shot tuning or training to prevent evaluation leakage.
